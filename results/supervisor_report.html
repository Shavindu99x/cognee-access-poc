Cognee access-control proof of concept

17 October 2026 · Cognee 1.6.4 · Python 3.12.15 · Isolation run 14:43 · Grant/revoke run 14:53

Result: the requirement is met at dataset level. Two users each have two documents in a Cognee GraphRAG system. When the HR user asks a finance question, Cognee searches only the HR graph and the answer is “I don't have that information.” The finance document is not in the retrieved chunks or in the text sent to the model. Asking for the finance dataset by name returns HTTP 403 from Cognee before any retrieval.

1. What was asked

Build a proof of concept with two users and four documents, two documents for each user. Retrieval must happen inside Cognee's GraphRAG, not by filtering results in application code. A user who asks about the other department must be told the information is not available, and the restricted document must not be fetched. The refusal has to come from Cognee.

2. What was built

A data admin ingested four documents into two datasets. Each dataset is one permission boundary. With access control on, Cognee stores a separate graph file and a separate vector database for each dataset. The two end users are not superusers.

3. Where Cognee makes the decision

  1. The caller passes the user into Cognee. Cognee identifies that user.
  2. Cognee reads its ACL table and keeps only the datasets that user may read.
  3. Cognee opens only those datasets' graph and vector files, then retrieves from them.
  4. That retrieved context is what the model sees.

This project's code does not remove forbidden text after Cognee responds. The tests record the datasets Cognee searched, the raw chunks, and the exact context given to the model.

The sentence “I don't have that information.” is set in the prompt so the model uses one wording when the retrieved context has no answer. The access decision is the earlier step: the other graph file is never opened.

7. The gap

Cognee 1.6.4 cannot keep one shared graph and authorize HR or Finance at the node. An ACL row is a person, a permission (read, write, delete, or share), and a dataset. It has no node, document, or field. With access control on, Cognee opens a separate graph file per dataset. It does not open one graph and then hide individual nodes.
RequirementThis proof
Two users, four documents, GraphRAGMet. Two documents per end user. Retrieval goes through Cognee's graph and vector search.
A restricted document is not fetchedMet. Shown without trusting the model sentence: raw chunks, keyword search, and the exact model context.
The refusal comes from CogneeMet for the access decision. The words “I don't have that information.” are prompt wording used when that context has no answer.
One graph, with a node-level checkNot available. One dataset would be one graph, and read on that dataset would expose every node, including the other department.

If all four documents were placed in one dataset, the two Kasun Silva nodes could become one node, and the HR user could traverse from the employee record into the vendor payments. A filter written in this project after Cognee returns results would be application filtering, which this proof was built to avoid.

Other limits to state in the review: permissions are per dataset, not per field. A superuser bypasses the ACL. The application still has to pass the correct user into the SDK; Cognee does not guess who is asking.
